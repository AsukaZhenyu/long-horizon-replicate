# Method Design

本文件定义 Horizon Weaver 的方法层。长期运行的 Agent 要在执行中保持状态、估计进展，并从自己的 rollout 更新行为。方法层的回答是两条运行时轴：**上下文管理**负责状态与经验，**导航**负责控制；学习发生在运行中，不设独立训练阶段。Cordis 提供组合运行时，使组件和依赖可以在运行中替换、回滚。

三个主张：状态与控制分开；学习在运行中发生；范式差异主要是控制拓扑与 provider 的组合，不是方法差异。默认基座冻结，学习与迭代都在运行时层（循环、工具、上下文、权限）；基座可训练时，同一套日志和信号可用于蒸馏。

## 1. 设计原则

| 原则 | 设计含义 |
| --- | --- |
| 两条轴 | 上下文管理负责状态与经验，导航负责控制；两者共享日志、预算和结果信号。 |
| 一条循环 | 构建状态、估计进展、选择动作、执行、观察、更新。 |
| 搜索优先 | 预算增加时先增加候选数、分支数、估计次数，不增加手写规则。 |
| 运行中学习 | 只从任务结果、估计信号和成本更新；学习是运行的一部分，不是独立训练阶段。 |
| 能力即插件 | 上下文管理和导航都是服务；实现是 provider；替换一个不影响其余。 |
| 日志即事实 | 会话日志只追加，是唯一事实源；上下文是每次请求从日志构建的视图。 |
| rollout 即经验 | 闭环轨迹是学习的基本单位；记录行为策略、状态视图、估计和结果，失败也保留。 |
| 回合内可改 | 当前 rollout 可以直接触发热替换；变更可验证、可回滚，只对当前 episode 生效。 |
| 结构压缩 | 上下文按 artifact 的结构组织成多分辨率树；单轮只展开焦点相邻节点。 |
| 导航即控制 | 状态估计和策略是一个回路的两半；它们共同学习，不拆成两个独立模块。 |
| 迭代按 generation | 候选组合先评估再替换；失败回滚到上一代。 |

## 2. 系统架构

### 2.1 Cordis 运行时

Cordis 是组合运行时：Service 是具名能力，Provider 是实现，Fiber 是实例状态，Effect 是可撤销副作用，Event 是观察与拦截点，generation 是一次完整组合。替换组件时，依赖它的 provider 自动卸载或重连，旧 effect 自动清理。上下文管理和导航因此可以独立热替换、失败回滚。

### 2.2 组件

| 组件 | 职责 | 对 agent 的可见性 |
| --- | --- | --- |
| 会话日志 | 追加记录任务、状态视图、动作、观察、artifact、估计信号、行为策略和成本 | 可读自己产生的部分 |
| 模型 | 产生候选动作、摘要、估计和判断 | 通过服务间接使用 |
| 工具 | 注册可调用的工具 | 可见 |
| 执行层（host） | 直接与终端、文件系统、代码运行时和渲染器交互；GUI 不在主范围 | 可见 |
| 上下文服务 | 从日志、长期记忆和经验构建状态 | 不可见 |
| 导航服务 | 估计进展与差距，产生并选择动作 | 不可见 |
| 评估服务 | 官方评分和隐藏测试 | 不可见 |
| 变异服务 | 回合内热替换与回合间 generation 的评估、切换、回滚 | 不可见 |

会话日志是持久事实，其余组件都可以从日志重建。上下文服务只读日志；导航服务和评估服务把结果追加回日志。这套组件加默认 provider 就是基础 Agent：它不区分训练和部署，启动后一直在运行；它提供稳定的服务契约和可替换的 provider 槽位，学习就是在运行中替换或更新这些槽位。

### 2.3 主循环

1. 任务进入，上下文服务从日志、长期记忆和经验构建当前状态。
2. 导航服务估计进展和距目标的差距，产生候选动作并排序。
3. 选中的动作分派给 host、上下文服务、子任务或结束提交。
4. 执行结果追加到日志；需要时估计信号也追加到日志。
5. 上下文服务按新日志重建状态，导航服务更新估计。
6. episode 结束，评估服务运行官方评分。
7. 评估结果进入运行中学习；评估停滞时进入变异服务，生成下一代运行时。

循环里没有任务分支。任务差异由 host、工具和估计 provider 承担。

### 2.4 为什么这样分

日志与上下文分离，是因为事实和视图的生命周期不同。日志要可回放、可审计；上下文要按预算、任务和焦点重建。

上下文与导航分离，是因为状态和控制是两类问题。上下文决定这一轮看到什么；导航决定下一步做什么。两者可以独立替换。

导航内部不把估计和策略拆开，是因为它们本来就是一个回路：估计给策略“还差什么”，策略给估计新的观察。拆开会诱导分别优化，联合学习才能利用耦合。

评估与导航分离，是因为 agent 需要过程反馈，但不能看到最终评分。导航调用可见估计器；隐藏测试只在 episode 结束后由评估服务运行。

## 3. 上下文管理

上下文是导航读写的状态。职责是管理工作记忆、长期记忆和经验，在 token 预算内构建本轮状态。

### 3.1 三层状态

**工作记忆**：当前任务、计划、焦点节点、部分结果、未决问题、最近的动作和观察。按结构组织，按预算展开。

**长期记忆**：artifact、节点摘要、引用、缓存。按版本管理；原始内容由 artifact 引用指向，不复制进上下文。

**经验**：过去 episode 的轨迹摘要、结果、失败类型、可复用策略。按状态特征建索引，按相似度检索；经验是数据，不是策略权重，也不等于原始日志。

日志是事实，长期记忆是事实的组织，工作记忆是本轮取用的部分，经验是过去事实中被标注了结果和策略的子集。四者不互相替代。

### 3.2 结构与压缩

**结构来源**：论文有章节、段落、论点；代码有文件、函数、语句；计划有目标、子任务、步骤；证明有引理依赖；图表有数据、坐标轴、系列和标注；位图有图层、区域和元素。结构由解析器或分析器提供，作为上下文 provider 的一部分；没有显式结构的文本按段落、标题和引用关系建树。跨节点引用（章节引用、import、引理依赖）作为可跳转的边，需要时沿边展开。

**节点与分辨率**：每个节点有一个缓存的粗粒度表示和一份原始内容。论文的根节点是 3–5 句核心论点，下一层是章节摘要，再往下是段落，叶子是原文；代码的根是模块职责，往下是函数签名与不变量，叶子是语句。树的深度不受限，展开是惰性的；节点或模型版本变化时缓存失效。

**单轮展开**：焦点随当前动作和估计信号移动，由导航指定。从根到焦点的路径以粗粒度保留；单次推理只展开焦点的父节点、兄弟节点和直接子节点，更远的祖先保持粗粒度，更远的后代不展开。展开深度由预算和焦点重要性决定；预算不足时优先保留父节点和兄弟节点。这样每轮输入由局部结构决定，不由总轨迹长度决定。

结构压缩与摘要不同：摘要压完就丢失节点边界和可导航性；结构压缩保留树的形状，任何节点都能按需重新展开。压缩按层缓存，同一节点在不同轮次可以以不同分辨率出现。

### 3.3 经验管理

| 问题 | 做法 |
| --- | --- |
| 存什么 | 任务特征、关键状态、策略、结果、失败类型、可复用片段；失败类型按可观测行为划分。 |
| 怎么索引 | 用任务类型、焦点节点类型、当前估计信号和已尝试动作构造检索键。 |
| 怎么取 | 按相似度和剩余预算取少量记录，压成简短提示放进工作记忆。 |
| 怎么用 | 影响导航的候选生成和估计先验，不直接修改策略权重。 |

### 3.4 可学习、可自我迭代、表达范围

| 维度 | 内容 |
| --- | --- |
| 可学习 | 写入什么、压缩到什么程度、检索哪些节点和经验、展开到多深，从下游结果更新；用节点和经验消融估计贡献。 |
| 可自我迭代 | 替换建树、粗粒度表示、展开策略和经验索引的 provider；只读日志，替换不改变事实。 |
| 表达范围 | 结构模态相关，接口模态无关；文本、代码、证明、图片各有解析器；无结构输入退化成时间树。 |

导航指定焦点和需要展开的节点，上下文服务返回状态和经验；上下文不替导航做决定，导航不直接改写日志。

## 4. 导航

导航是控制回路：读状态、估计进展、选择动作、写回状态。

### 4.1 状态估计

状态估计回答三个问题：完成了什么、还差什么、信号是否可信。它是带置信度的进展估计，二值判定只是特例。

| 估计器类型 | 例子 | 特点 |
| --- | --- | --- |
| 精确 | Lean 内核、pytest、schema、数值容差、答案匹配 | 确定、无判断噪声、成本中等 |
| 判断 | LLM 或 VLM 按 rubric 打分、成对比较 | 有噪声、成本低、需要校准 |
| 人类 | 抽样复核、标注 | 成本高、置信度高 |
| 统计 | 多次采样的一致性、置信区间 | 成本随样本数增长 |

**路由与校准**：按 artifact 类型、所需置信度和剩余预算选择估计器；记录每个估计器在任务族上的混淆矩阵，校准分数与置信度；多信号按可靠性聚合。

**目标检验**：候选动作里保留结束提交；是否允许提交由目标检验决定。开放任务的 goal 由 agent 提出，版本和变更理由写进工作记忆；进展停滞时可以修改 goal。

### 4.2 策略

**动作空间**：全部工具，加上四类内建动作：调用估计器、读写上下文、派生子任务、提交答案。工具是插件，新增工具不改循环。

**搜索形态**：顺序执行和分支搜索共用一套机制。每步产生若干候选，按价值和成本选择；分支时对子任务建树，预算按节点分配；回退时从日志恢复。搜索深度、候选数量和分支因子由剩余预算决定。

**估计与策略的耦合**：估计给策略“还差什么”，策略执行后的观察又成为估计的输入。两者共享价值表示：价值既用于排序候选，也用于判断进展是否值得继续。学习时联合更新。

### 4.3 可学习、可自我迭代、表达范围

| 维度 | 内容 |
| --- | --- |
| 可学习 | 价值函数、候选排序、估计器路由与聚合，从回报、最终结果和中间信号更新。 |
| 可自我迭代 | 替换导航 provider、工具和估计器插件；候选 provider 在留出任务上按同一预算评估后热替换。 |
| 表达范围 | 动作和观察是类型化联合；文本、代码、图片、Lean 文件都是 artifact；估计器声明支持的媒体和规范类型。 |

## 5. 运行中学习

### 5.1 rollout 是学习的基本单位

rollout 是一次完整执行轨迹。导航是控制，控制的监督只能来自闭环轨迹：单步的输入输出说明不了动作的后果，只有把状态、动作、观察、估计和最终结果连起来，才知道某个动作把 agent 带到了哪里。价值、进度估计、检索策略、估计器校准、失败分类，都是 rollout 的函数。

这与 ML 范式有三点不同：没有独立训练阶段，学习就是运行的一部分；没有以数据集为中心的组织方式，日志是经验流；没有冻结的部署，组件在运行中被替换或回滚。留出任务只用于测量是否退化，不参与拟合。可学习性因此是架构属性：稳定的服务契约、可替换的 provider 槽位、运行时的更新钩子。

### 5.2 四类用法

| 用法 | 做法 |
| --- | --- |
| 回报标注 | 每个状态之后到终点的结果累加，更新价值与进度估计；失败轨迹也保留。 |
| 分支反事实 | 同前缀不同动作形成配对比较，估计优势；搜索树同时是数据。 |
| 经验与技能 | 成功轨迹做案例，失败轨迹做模式库，子序列做技能片段。 |
| 校准与失败挖掘 | 估计信号与最终结果构成校准样本；失败聚类提出新检查项。 |

### 5.3 回合内学习

回合内学习用当前 rollout 直接改变后续步骤使用的组件和组合。它不是把轨迹放进上下文，而是换上下文展开策略、换估计器路由、加完成门、写新工具、改控制图连接，然后在同一 episode 里继续。

Cordis 在这里不可替代：批次学习只需要训练循环和参数存储；回合内学习需要运行中替换组件、依赖自动重连、替换可撤销。provider 热替换、inject、effect 清理、scope 隔离和 generation 回滚正好对应这些需求。

回路是六步：

1. 诊断：导航的状态估计识别循环、过早提交、上下文丢失、格式错误或估计器不一致。
2. 检索：上下文管理取回当前前缀的相关节点和相似经验。
3. 提出变更：变异服务给出针对诊断的最小改动，形式是 prompt、配置、provider 或控制图连接。
4. 验证：能分支就派生分支比较进展；不能分支就做影子重放；再不行用小预算在线 bandit。
5. 提交或回滚：提交走热替换，回滚走 effect 和 generation。
6. 记录：变更、验证结果和回滚原因写入日志。

热替换挂在 episode 作用域，结束时由 effect 清理；只有通过回合间回归检查的变更才进入全局 generation。变更花预算，所以它是导航的决策；变更间隔有下限，连续回滚要停止。

### 5.4 三个可学习组件

导航策略、状态估计、上下文管理。前两个在导航内部联合更新，因为它们共享价值表示；第三个独立更新，但使用同一份日志和结果信号。三者的更新都在运行中发生，不依赖独立训练阶段。

### 5.5 数据边界与更新方式

rollout 要能复用，日志至少要记录：行为策略标识、状态视图、估计信号、最终结果；有分支时记录父节点。行为策略标识处理旧数据与当前策略不一致；状态视图重建上下文；估计信号用于校准；结果用于回报。

学习信号来自任务流本身；留出任务只用于测量。失败轨迹全部保留，只留成功会带来选择偏差。更新方式是运行中更新：回合内热替换，回合间用经验流更新组件；日志回放用于复盘和校准。策略种群用 bandit 或进化，权重用回归和校准，基座可训练时增加蒸馏。所有更新只改 provider 的参数或组合，不改评估服务、任务规范和预算记账。

## 6. 自我迭代

这一节讲回合间的 generation 迭代；回合内热替换在 5.3 节。两者共用变异服务和 effect 机制，验证信号不同：回合内用当前 episode 的剩余预算，回合间用留出任务的回归检查。

触发条件是固定间隔、评估停滞或人工请求。每次先写变更计划：变更级别（热替换、重建 generation、替换运行时）、影响范围、预期收益、评估方案、回滚方案。流程是生成候选、合约测试、留出任务回归检查、切换 generation、健康检查、提交或回滚。

变更范围包括上下文 provider、导航 provider、工具、prompt 和策略参数；评估服务、任务规范和预算记账不参与变更。Cordis 的 effect 保证替换无残留，变异服务把候选、提升和回滚记录为事件。

## 7. 基本对象

| 对象 | 含义 |
| --- | --- |
| artifact | 产物引用，包含位置、媒体类型和内容哈希 |
| 动作 | 工具调用、估计调用、上下文操作、子任务、结束提交 |
| 观察 | 动作返回的类型、内容和 artifact 列表 |
| 预算 | token、实际时间、估计次数三种上限 |
| 使用量 | 实际消耗的 token、时间和估计次数 |
| 任务规范 | 任务标识、指令、输入 artifact 和预算 |
| episode | 任务、状态视图、事件、估计信号、分支关系、行为策略、结果和使用量 |
| 记忆节点 | 标识、父节点、粗粒度表示、artifact 引用和版本 |
| 经验记录 | 任务特征、关键状态、策略、结果和失败类型 |
| 变更记录 | 触发诊断、变更内容、影响范围、验证结果、提交或回滚 |

这些对象是方法层与 host、估计器、评估器之间的共同语言。新增任务或模态，改变的是提供者，不是对象的形状。

## 8. 适用范围：现有 Agent 范式的聚类

聚类按两个维度：控制拓扑，和学习内容。领域和模态是 provider 的差异，不是架构的差异。

### 8.1 控制拓扑

**Loop**：一个策略顺序执行“观察—动作”。ReAct、CodeAct、文件与终端 agent、工具调用属于这一类。GUI agent 也是 Loop，但不在本文主范围。

**Tree**：在 Loop 上加分支、回退和价值估计；分支在同一个导航实例内，共享状态和预算。ToT、LATS、MCTS、带验证器的证明搜索属于这一类。

**Graph**：多个节点按依赖连接并传递状态。Plan-execute、LangGraph 式工作流、AutoGen/CrewAI 式角色分工属于这一类。

**Stack**：节点派生子节点，父节点暂停、子节点运行、结果返回；子节点是新的导航实例，有自己的状态和预算。Spine 式子任务树、subagent、层级 manager-worker 属于这一类。

真实系统通常是组合：AutoGPT 是 Loop + Stack + Graph，MetaGPT 是 Graph 上挂角色，LATS 是 Loop + Tree，MemGPT 是 Loop 上挂长期记忆。拆成四种拓扑后，剩下的差异大多是接口和估计器。

### 8.2 学习内容

**信息**：只改本轮看到的内容，如 ReAct 的 scratchpad、Reflexion 的反思、MemGPT 的记忆。

**权重**：改模型参数，如微调、蒸馏、RL。

**运行时组件**：改 provider、工具、控制图连接；Cordis 的热替换和 generation 属于这一类，本文的方法主要在这里。

三者不是互斥层级，而是三种变更内容：信息变更通过上下文 provider 实现，权重变更通过模型 provider 实现，组件变更通过热替换实现。本文把三者都放在运行时，不需要为前两类另写一套。

### 8.3 范式表

| 范式 | 拓扑 | 学习内容 | 本文如何覆盖 |
| --- | --- | --- | --- |
| ReAct / CodeAct / 文件与终端 agent | Loop | 信息 | 导航 provider + 上下文管理 |
| Reflexion / MemGPT | Loop | 信息 + 记忆 | 上下文管理 + 回合内变更 |
| ToT / LATS / MCTS | Tree | 搜索价值 | 导航分支 + 状态估计 |
| Plan-execute / LangGraph | Graph | 信息 + 工作流 | 控制图 + 每节点一个导航实例 |
| AutoGen / CrewAI / MetaGPT | Graph | 信息 + 角色通信 | 多导航实例 + 上下文交换 |
| Spine / subagent | Stack | 委派 | 嵌套导航 + scope + 预算分配 |
| STOP / Gödel / Cordis creation | Loop | 运行时组件 | 回合内热替换 + generation 迭代 |

### 8.4 为什么范围广

长期运行的 rollout 学习不依赖具体拓扑；它依赖每个节点都有状态、动作、估计和结果。四种拓扑都满足。两个轴固定，拓扑只是组合方式，接口和估计器是 provider；新增范式通常只是新增组合或 provider，不改方法层。

聚类可以用公开架构做编码验证：每个架构记录拓扑、学习内容、接口和估计器，两人独立编码并报告一致性。如果大多数架构落在少数格子里，“大差不差”就是可测的。

## 9. 与现有实验的对接

执行层（host）服务包装现有任务执行契约：输入动作，返回观察；通过 stdio 或 HTTP 调用 Python runner，Cordis runtime 与实验环境分进程。主套件的 host provider 是 OfficeEditBench、ChartMimic/ChartQA、PPTAgent/PPTEval、Paper2Poster/DECKBench、ECHO 和数学套件；TB/LHTB/CORE/MLE 已移出主套件，只作公开结果引用。新增任务只需提供任务规范、host provider 和评估 provider。

评估服务包装官方测试评分器和隐藏测试；导航的状态估计包装 Lean、可见测试、答案匹配和 VLM judge。两者不共享隐藏信息。

会话日志承接现有轨迹记录；上下文服务取代现有上下文策略的固定规则，并新增长期记忆和经验存储。导航 provider 包括 Base、Sentry、Recuris、RRSI 和 Spine 重实现：Base 只有策略半边，Sentry 加了估计与干预，Recuris 加了完成门，RRSI 换了描述子，Spine 把动作换成子任务派生。

指标包括 pass@E、E-to-success、每次成功所需的估计次数、每条轨迹的有效监督样本数、回合内变更的净收益与回滚率、变更接受率、generation 增益，以及每次推理的上下文 token 与展开节点数。

评估问题有六个：联合导航相对分开优化估计和策略提升多少；结构压缩相对固定窗口和摘要提升多少；经验检索相对无经验提升多少；用回报和分支反事实更新导航相对只用最终结果提升多少；回合内热替换相对只在回合间更新提升多少；自我迭代是否随 generation 提升且不是评测波动。

数学面板的任务集、预算和统计按 Math-Experimental-Design.md 执行；本文件定义共同的方法层。

## 10. 实现顺序

1. 用现有轨迹做一次性初始化：状态回报、失败聚类、估计器校准曲线；不是训练阶段。
2. 搭 Cordis 根 Context、会话日志、host 和评估服务，跑通一条 Base episode。
3. 接固定上下文 provider 和精确估计器 provider；导航先用固定策略，复现 Base 与 Sentry。
4. 接结构压缩：解析器、节点树、焦点展开和缓存。
5. 接经验存储与检索，跑重复任务族对照。
6. 联合更新导航价值函数与状态估计，用日志回放做复盘。
7. 做估计器路由与校准，接入判断型 provider。
8. 做回合内热替换：诊断、最小变更、分支或影子验证、回滚；先在单题跑通。
9. 做回合间 generation 迭代：留出任务回归检查、切换、回滚。
10. 接入全部 host 和估计器，跑预算扫描与多 seed。

目录约定：方法实现放在 packages 下的 runtime、services、providers、hosts 和 tools；文档放在 docs/plan；候选插件、日志和图表放在 tmp。
